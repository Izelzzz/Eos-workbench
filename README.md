# Eos Workbench

Eos 是一个自己部署的多 agent 开发平台。你在网页上写下需求，Eos 让几个分工不同的 agent 依次完成规格、开发、测试和评审，并把结果作为一个 PR 交给你。

> Eos（厄俄斯）是希腊神话里的黎明女神。

## 它能做什么

- **把一个需求做成一个 PR**：agent 写规格、写代码，平台运行测试，评审 agent 检查改动，最后由平台推送分支并开 PR。
- **按团队的规则做**：每个阶段要交出什么、要通过哪些检查，写在工作流里，由平台用程序检查，不依靠 agent 自己说「做完了」。
- **限制 agent 能做的事**：每个角色能用哪些工具、能改哪些路径，由团队在平台上统一配置。越界的改动不会进入提交。
- **让你看到全过程**：每一次模型请求、工具调用、检查结果、耗时和 token 都能在任务页上查看。
- **需要你时才找你**：agent 遇到拿不准的地方会向你提问，问题集中显示在页面上。
- **从做过的任务里改进规则**：平台归纳评审意见和检查失败，生成改进提案，你批准后才生效。

## 一个任务是怎样运行的

内置的 `standard` 工作流有五个阶段：

| 阶段 | 谁来做 | 产出 |
|---|---|---|
| 规格 | 规格 agent | `docs/spec.md`：背景、范围、验收标准 |
| 开发 | 开发 agent | 代码改动，以及 `docs/changes.md` |
| 测试 | 平台运行 `npm test` | 失败时把输出交回开发 agent 修改，最多 5 轮 |
| 评审 | 评审 agent | 和开发 agent 来回对话，直到通过。5 轮不通过时请规格 agent 重新确认，仍不通过就问你 |
| 交付 | 平台 | 推送任务分支，开 PR |

每个任务在自己的分支 `eos/<任务id>` 和独立的工作目录里进行，不改动你当前的工作目录。测试命令和各阶段的要求可以在网页的「团队约定」里修改。

## 快速开始

在自己的电脑上试用。需要 Node 24.9 以上、git，以及一个 DeepSeek 的 API key。

1. 安装并构建网页。

   ```bash
   git clone https://github.com/Izelzzz/Eos-workbench.git && cd Eos-workbench
   npm install && npm run build:web
   ```

2. 设置 API key，启动。

   ```bash
   export DEEPSEEK_API_KEY=<你的 key>
   npm run eos -- web
   ```

3. 打开 http://127.0.0.1:4317 ，点「新建任务」：填一个本机 git 仓库的路径，选择工作流，写下需求。

环境有问题时，运行 `npm run eos -- doctor` 查看哪一项没有通过。

## 怎么用

### 网页

| 页面 | 用来做什么 |
|---|---|
| 任务 | 查看所有任务；新建任务 |
| 任务详情 | 查看每一步的对话、工具调用、检查结果和改动；回答 agent 的提问；继续、重试或中止任务 |
| 团队约定 | 维护工作流、约定文档、Agent 模板和技能。每次保存是一个新版本 |
| 凭据 | 保存模型 key 和 Git 令牌。需要先设置主密钥，见部署文档 |
| 代码托管 | 注册 GitHub App，用 GitHub 账号授权 |
| 统计 | 按阶段和角色查看耗时、token 和瓶颈 |
| 改进 | 查看改进提案和依据，批准或拒绝 |

服务重启后，没有运行完的任务自动继续。

### 命令行

命令行和网页使用同一份数据。数据默认在 `~/.eos`。

```bash
npm run eos -- run --repo <仓库路径或 GitHub 地址> "<需求>"
```

| 命令 | 作用 |
|---|---|
| `run` | 创建任务并运行 |
| `status [任务]` | 列出任务，或查看一个任务 |
| `log <任务>` | 完整的对话记录、耗时和 token |
| `answer <任务> "<回答>"` | 回答 agent 的提问 |
| `resume <任务>`、`retry <任务>`、`abort <任务>` | 续跑、重试、中止 |
| `workflows` | 列出内置的工作流 |
| `doctor` | 检查运行环境 |
| `web` | 启动网页 |
| `improve`、`proposals`、`approve`、`reject` | 生成、查看、批准、拒绝改进提案 |

完整的参数见 `npm run eos -- --help`。

### 使用 GitHub 上的仓库

新建任务时，「仓库」一栏可以直接填 `https://github.com/<owner>/<repo>`。平台自己克隆仓库，任务结束时推送分支并开 PR。

访问私有仓库、推送和开 PR 需要凭据。先设置主密钥（见部署文档），再选一种方式：

- 在「凭据」页添加名为 `github.com` 的 Git 令牌；
- 或在「代码托管」页注册 GitHub App，并用 GitHub 账号授权。这样开出的 PR 作者是你本人。

## 使用前要知道的

- **没有登录。** 能打开平台地址的人，都能建任务、看所有记录、使用平台保存的凭据。默认只监听本机地址；部署到服务器时按部署文档配置访问方式，不要直接暴露到网络上。
- **模型只支持 DeepSeek**，默认是 `deepseek-flash`。可以按角色选择模型。
- **只适合互相信任的个人或小团队。** 任务之间没有隔离：一个任务的 agent 能读到同一台服务器上其他任务的代码和记录。
- **agent 能访问网络**，不受限制。
