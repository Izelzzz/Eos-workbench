# 第 4 块 PR5：完整流程 E2E（真实模型）

验收标准 ⑦：跑一组任务 → 生成提案 → 批准 → 新任务用上新版本 → 在对比页上看到两组。

脚本是 `scripts/improve-full-e2e.ts`。命令：先运行 `npm run build:web`，再运行 `node --import tsx scripts/improve-full-e2e.ts`。

## 做法

场景和前几个 PR 一样：团队规则「导出函数要有带 @example 的 JSDoc」只写进 reviewer 模板第 2 版，开发看不到。

1. **改进前**：并行跑 sum、max、avg 3 个 standard 任务。
2. 调用接口生成提案（真实的 improver），只针对这 3 个任务。批准其中把 @example 规则写进 developer 模板的那一条，得到 **developer 第 2 版**。
3. **改进后**：用同样 3 个需求再跑一遍。
4. 核对数据库里的版本、对比接口的数字和页面显示。

agent 提问时，脚本自动选第一个选项（没有选项就回答「按你的判断来」）；任务失败时自动重试。各任务的提问次数如下（独立审查读数据库核对）：
- 改进前：p48 2 次、i60 3 次、z6g 0 次
- 改进后：6tg 0 次、wso 1 次、roi 3 次

「6 个任务都完成」是在这样自动回答之后得到的。avg 改进后最后一次评审说「用户确认保留 docs/changes.md」，这里的「用户」就是脚本的自动回答。

## 结果（代码 `a21c5d1`，工作区没有未提交的改动：`report.json`、`run.log`）

9 项核对全部通过：

- 生成了把 @example 规则写进 developer 模板的提案，批准后生成了第 2 版。
- 改进前的任务用的是 developer 第 1 版，改进后的任务用的是第 2 版（读数据库里的任务元数据确认）。
- 6 个任务都完成了。
- 对比接口里，改进前、改进后各有 3 个任务，样本足够。
- 两组的评审轮次和检查失败，和直接从数据库独立复算的值一致。复算口径是：数回复里带 `verdict` 字段的评审调用，没有用 `parseVerdict`。
- 统计页和提案页都显示了对比区：8 行，有变化列，没有"样本不足"的提示。截图见 `insights-compare.png`、`proposal-compare.png`、`proposal-compare-390.png`。
- 390 宽下，提案页和统计页都不横向滚动；页面没有脚本错误。

## 处理独立审查之后的复核（不调用模型）

独立审查之后的修复只改了这几处，没有改分组和指标的计算：
- 显示格式：前后相等时显示 0%，完成率的变化按百分点算；
- 标签：「补齐次数」改为「补齐次数（含按用户指示）」；
- 服务端：同一个请求里，每个任务的数据只读一次。

修复之后，我用最终代码在这次 E2E 的数据目录上重新启动服务（不调用模型）做了复核：
- `/api/improve/comparisons` 返回的两组平均值，和 `report.json` 里记的逐项相同；
- 统计页的对比区：完成率的变化显示「0」，前后相等的行显示「0%」；
- 页面没有脚本错误。

`insights-compare.png` 是这次重拍的；`proposal-compare*.png` 来自原来那次运行。

## 两组的数字（每个任务的平均值）

|---|---|---|
| 完成率 | 100% | 100% |

| token（输入 + 输出） | 28.3k | 37.3k |
| agent 时长 | 1m43s | 2m14s |

**平均数没有体现出来的部分**：证据的具体内容。

- 改进前：3 条证据都是评审要求补 @example。
- 改进后：**没有任何关于 @example 的证据**。
  - 两个任务的评审一次就通过了。
  - avg 任务有 3 条证据，都和 @example 无关：
    - 评审指出开发新增了 docs/changes.md，超出了规格写的"只改这些文件"，要求修改了两次；
    - 开发试图改 docs/spec.md 来对齐范围，这个改动超出了它能写的路径，被平台撤销了。
  - 前几次 E2E 里，improver 也就这个问题提过提案（改工作流里 spec 的说明，或在研发约定里写明 docs/changes.md 不算越界），这次没有批准。

改进后 token 和时长变多，主要也来自这个 avg 任务的 3 轮评审。

## 不能证明的

- **因果关系**：每组只有 3 个任务，模型有随机性。改进后 @example 问题消失和这次修改是一致的，但样本太少，不能说明是它带来的。
- 对比区只给平均数，看不出证据的具体内容变了没有。要看内容，得点进任务或提案的证据。
