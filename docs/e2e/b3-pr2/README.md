## 实时页面（`scripts/web-e2e.ts`，真实模型，全程浏览器操作，中途杀掉 Web 服务再重启）

每一轮同时运行一个采样脚本：

- 每 5 秒从 `/api/tasks/<id>` 取一次阶段数据，写进 `samples.jsonl`；
- 任务进行中时截阶段表（`live-*.png`），完成后再截一张（`live-done.png`）。

| 轮次 | 代码 | Web E2E | 发现 |
|---|---|---|---|
| run1 | 第一版 | 10/10 | 规划阶段的调用跑了约 4 分钟，期间全部显示成「平台开销」；任务刚开始的约 30 秒，第一个阶段时长是 0 |
| run2 | 正在跑的调用单独算「进行中」；第一个阶段从任务创建时算起 | 10/10 | 调用中途 agent 提问时，提问之前跑的约 23 秒仍然算成平台开销，要等调用结束才归到 agent |
| run3 | 正在跑的调用从它开始时算，中途等用户的时间扣掉 | 10/10 | 规划阶段从开始到结束：进行中随时间增长，等用户单独算，平台开销一直是 0；调用结束后归到 agent |

run3 的 `samples.jsonl` 里，plan 进行中时：

- 3.7s → 24.0s：全部是「进行中」；
- 提问期间：「等用户」增长，「进行中」不变（两次采样之间 agent 又跑了一小段，所以略有增长）；
- 调用结束后：agent 162.4s，等用户 8.6s，平台开销 0。

run2、run3 的采样到最后有几条 `fetch failed`，是 E2E 脚本结束时关掉了服务。run2 没有拍到完成后的截图，原因相同。

run2 的采样进程当时没有及时停掉，在 run3 期间又写进了 55 条 run3 的数据（独立审查发现）。这些行已经按时间戳删掉：只保留早于 run3 第一条采样（1795235090623）的 75 条。

表头里「运行中」原来叫「进行中」，和阶段名后面的「进行中」标签重名，审查后改了名。run1–run3 的截图上还是旧名字。
