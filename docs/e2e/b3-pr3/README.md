# 第 3 块 PR3：统计页 E2E 证据

脚本：`scripts/insights-e2e.ts`。

## 做了什么

1. 在全新的数据目录里启动 `eos web`。
2. 用真实 deepseek 模型跑 3 个任务，都在同一个示例仓库上：
   - 2 个 `standard` 工作流任务，用到内置模板 spec-writer、developer、reviewer；
   - 1 个 `feature` 工作流任务，角色直接写在工作流里。
3. agent 的提问由脚本自动回答。
4. 全部完成后，用浏览器打开统计页。

## 核对（8/8 通过）

1. 3 个任务都完成。
2. 统计页的任务数一致。
3. 每个阶段的时长、agent 时长、调用数，都等于各任务详情页（`/api/tasks/:id` 的 `metrics`）里这个阶段的数字之和。
4. 每个工作流的输出 token 等于各任务之和。
5. spec-writer、developer、reviewer 三个模板都在，调用数等于各任务里用这个模板的角色的调用之和。
6. 每个工作流都有瓶颈，并且就是它最耗时的阶段。
7. 页面没有脚本错误。
8. 手机宽度下页面不横向滚动。
