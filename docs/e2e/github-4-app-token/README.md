# GitHub 接入 4：GitHub App 的短期令牌（回归 E2E）

## 这次 E2E 证明什么

真实的 GitHub App 要在用户的浏览器里注册，平台的注册页在下一个 PR，所以这次 E2E **只跑没有配置 App 的情况**。它证明三件事：

- 平台访问远程仓库时，选认证的流程改成了"App → 个人令牌 → 匿名"；
- App 出错时直接报错；
- 用 App 访问失败后作废缓存。

这三处改动之后，没配 App 时的克隆、推送、开 PR 都没被改坏。下面这几条在没配 App 时根本不会执行，所以这次 E2E **没有覆盖**：

- 换 App 令牌；
- 缓存；
- 把令牌登记进统一遮蔽；
- 托管平台对象只建一次后，缓存的复用。

```
EOS_MASTER_KEY=<随机> EOS_E2E_REPO=https://github.com/Izelzzz/eos-e2e-sandbox EOS_E2E_GIT_TOKEN=<随机占位值> npm run e2e
```

- **跑的代码**：处理完独立审查之后的 aa411f2。审查之前在 e9ec41f 上也跑过一次，同样 15/15，那次开出的是 PR #3。
- **结果**：15/15，见 `e2e-report.json`，完整输出见 `e2e-run.log`。GitHub 上开出了 PR #4；用同一个分支再开一次，复用的还是 #4。
- **认证是代理做的**：平台持有的个人令牌是占位值，真正的认证由代理用会话的 GitHub 连接完成。所以"照常"只证明这条代码路径没被改坏，证明不了 GitHub 接受了平台发出的令牌。

## App 这条路径的证据

只来自模拟接口和单元测试：

- `tests/mirror.test.ts` 里「GitHub App」开头的几条。用的是测试服务模拟的 App，它会：
  - 用公钥校验 JWT，包括有效期不超过 10 分钟；
  - 按仓库发令牌，仓库名不分大小写；
  - 令牌会过期，也能被吊销。
- `tests/github-app.test.ts`：JWT 的格式和签名；同时来的多个请求只换一次；换取失败不缓存；没装到仓库；私钥必须是 RSA。
