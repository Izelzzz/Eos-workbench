# 第 1 块 E2E：团队约定 + 交付物检查 + 测试失败退回开发

脚本：`scripts/pipeline-e2e.ts`。全程浏览器操作，真实模型（deepseek-flash）。每次运行的 `report.json` 里记录了代码提交号和工作区是否有未提交改动。

## 人为设置（如实说明）

1. 在约定页把开发节点的任务说明改成「先不要写 docs/changes.md，平台检查会提醒你补」，让交付物检查必然先失败一次。
2. 测试节点改用平台持有的验收测试（在 worktree 外，开发看不到）。
3. agent 在页面上提问时，脚本自动点第一个选项（没有选项时填一句"按你的判断选最合理的做法"）。run2 回答了 3 次，记录在 `steps.log` 和 `report.json` 的 `answers`。
4. 第 2 次运行在验收测试里加了一条需求没写的用例（大写单位 `1H30M`），确定触发「测试失败 → 退回开发」。它证明的是退回机制，不是模型会漏掉边界情况。
