# 第 4 块 PR1：证据归纳 E2E（真实模型）

脚本：`scripts/evidence-e2e.ts`。命令：`node --import tsx scripts/evidence-e2e.ts`（加 `--verify` 只对上次的数据库重新核对）。

## 做法

1. 新建示例仓库（`npm test` 即 `node --test`），用全新的数据目录启动 `eos web`。
2. 把一条团队规则**只写进 reviewer 模板**，存成第 2 版：「每个导出的函数都要有带 @example 的 JSDoc，没有就要求修改」。
   开发看不到评审的提示词，所以多半不知道这条规则。这正是后面几个 PR 要让改进提案发现的情形。
3. 发起 2 个 `standard` 任务（sum、max）。提问自动回答，失败自动重试。
4. 两个任务都结束后，直接读数据库，对两个任务算证据，再和原始记录独立核对。

## 结果（`report.json`、`evidence.json`、`run.log`）

7 项核对全部通过：

| 核对 | 结果 |
|---|---|
| 所有任务都完成 | ✓ 2/2 |
| 证据 id 唯一，格式是 `任务:日志下标[:子项]`，并且指向日志里同一时刻、类型对得上的条目 | ✓（独立审查后加了类型核对，用 `--verify` 对同一个数据库重新核对） |
| 检查失败的证据条数 = 原始 events 表里没通过的检查结果数 | ✓（0 = 0） |
| 评审要求修改的证据条数 = 日志里评审没通过的次数（按评审调用之后的下一条日志独立判断，不用 `parseVerdict`） | ✓（2 = 2） |
| 归到 developer 模板的证据 = 被评判角色用 developer 模板的证据 | ✓ |
| 任务用的是 reviewer 第 2 版 | ✓ |
| 至少一条评审要求修改的证据提到这条团队规则，并归到 developer 模板 | ✓ |

证据（`evidence.json`）：

- `t26112105383940g:9`、`t261121053839zq4:9`：类型都是 `review_changes`，节点 `review`，被评判角色 `developer`。内容是评审结论，都指出「导出函数缺少团队规则要求的 @example」。
- 按约定汇总：
  - `developer` 模板 v1：用到的任务 2 个，其中有证据的 2 个，评审要求修改 2 次；
  - `write-changes` 技能、`研发约定` 文档、`standard` 工作流：同样都是 2 次；
  - `reviewer` 模板 v2、`spec-writer` 模板：有证据的任务 0 个。

## 没覆盖到的

- 真实数据里没有检查失败、打满轮次、格式重试、越界撤销、调用失败这几类证据，它们只有单测覆盖（`tests/evidence.test.ts`）。
- 调整场景的过程：
  - 前两次运行把团队规则写进仓库里的检查脚本，第一次是明文，第二次改成 base64 编码。
  - 两次 agent 都先读懂了规则、一次就照做，所以 4 个任务都没有产生任何证据。
  - 那两次各 6 项核对，都是 5/6，没过的是「至少一条检查失败的证据提到团队规则」。日志见 `attempt1.log`、`attempt2.log`。
