# Eos 路线图

- 状态：2026-11-24 确认优先级
- 产品背景：Notion「Eos 产品文档」（AI 项目数据库，项目名称 Eos）
- 用法：每一项是一块工作，拆成几个依次合并的小 PR（见 `CLAUDE.md`）。开始一项之前先列拆分和验收标准，用选择卡片确认。做完在本文件把状态改成「完成」并写上 PR 号。

## 方向（已定）

- **定位**：团队共用的云端执行环境（所有 agent 的行为对团队可见）+ 平台强制的规则和验收链 + 多角色共用。
- **押注不变的东西**：验收标准、程序化的检查、证据链、版本、审批、trace。流水线（规格 → 开发 → 测试 → 评审 → 交付）只是可替换的模板，不把顺序写死。
- **agent 在服务端跑**：实现不依赖「平台和用户在同一台电脑上」。
- **执行器中立**：模型质量是硬要求。每家 agent 用它自己最完整的接口，由 `src/executor/types.ts` 的 `Executor` 接口抹平差异。dsh 保留为执行器之一。
- **凭据只由平台持有**：agent 看不到令牌；提交、推送、开 PR 都由平台完成。
- **加严容易、放宽要人批**：新增检查或规则可以由 agent 提出；放宽或删除由人决定。
- PoC 阶段的 ADR（001–004）是验证记录，不再作为约束；和本文件冲突时以本文件为准，并补一份新的 ADR。
