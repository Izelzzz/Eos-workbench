# 研发约定

团队所有 agent 都遵守这份约定。它由平台注入到每个会话的开头，修改后对新任务生效。

## 交付物

- 每个阶段的交付物写在仓库里约定的位置，用 Markdown，章节标题和工作流里要求的一致。
- 交付物写给下一个阶段的人看：结论在前，细节在后，不写空话。

## 代码

- 只做需求和规格里要求的改动；发现别的问题记在交付说明里，不顺手修。
- 新增或改动的逻辑要有测试，提交前在本地跑通。
- 不执行 git commit、push、merge、rebase：提交由平台负责。

## 沟通

- 需求有歧义且会影响做法时，向用户提问，不要猜。
- 收到评审意见或检查失败时逐条处理：修改，或者带着理由说明为什么不改。
