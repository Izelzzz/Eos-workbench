# 改界面的方法

改 `web/src` 下的页面、组件、样式或界面上的文字时，按下面的顺序做。

## 长什么样

依据是用户认可的设计稿 `docs/design/workbench.html`（浏览器直接打开就能点）。新做或重做页面前，先做一版能在浏览器里打开的原型给用户看，用户认可了再写页面代码（见 `CLAUDE.md` 的「改界面按 ui skill」）。

### 七条原则

1. **克制。** 页面几乎只有黑、白、灰。强调色（`accent`）全站只有一个，只表示「等你处理」：标题前的小圆点、卡片上的类型、任务清单里等人的那几行。别的地方不用颜色。
2. **一屏只有一个浮起来的东西。** 当前要处理的卡片用 `Card`（有阴影），其余内容平铺在背景上，不加外框。
3. **用留白和细线分区，不用边框和底色。** 列表的行与行之间一条细线；区块之间靠间距（页面左右 40px、区块之间 44px，窄屏 16px 和 32px）。
4. **标题不抢内容。** 区块标题是小号的灰字（13px、`text-ink-2`）；卡片的标题才是大字（`CardTitle`）。
5. **主操作是黑色**（暗色主题下是白色）。一组按钮里只有一个主操作，其余用 `outline` 或 `ghost`。
6. **状态用形状表达，颜色只做补充。** 选中的选项是墨色边框加实心的勾；进度是一小段一小段（工作流有几个节点就几段）。
7. **动效短，而且有含义。** 悬停只变颜色或透明度（150ms，主按钮淡到 0.86），不移动、不缩放；做完一件事，卡片淡出、下一张补上。系统设置了减少动态效果时全部关掉（组件已带 `motion-reduce:`）。

### 组件对照

| 设计稿里的 | 组件 |
|---|---|
| 当前卡片：类型、标题、引导语、底部按钮 | `Card`、`CardHeader`、`CardTitle`、`CardDescription`、`CardFooter` |
| 问题和选项、「其他」输入 | `OptionGroup`、`Option`、`OptionOther` |
| 范围 — 编码 — 汇总 | `Steps` |
| 「第几件 / 共几件」的下拉 | `Menu`、`MenuTrigger`、`MenuContent`、`MenuItem` |
| 过程 / 改动 | `Segmented`、`SegmentedList`、`SegmentedItem`、`SegmentedPanel` |
| 改动、测试、评审这几行 | `InfoList`、`InfoRow` |
| 浅底的补充说明 | `Note` |
| 进行中的任务清单 | `TaskList`、`TaskRow`（等人的传 `waiting`） |
| 等你处理的小圆点 | `AccentDot` |

- 状态色（成功、失败、进行中）设计稿还没定，现在沿用旧界面的取值，只用于状态标签、trace 和阶段图。需要新的状态表达时先和用户确认，不拿强调色代替。
- 主题色以后可能换：只改 `tokens.css` 里的 `--accent` 和 `--accent-soft`，组件里不写死橙色。

## 第一步：用现有的组件和令牌

| 要什么 | 用什么 | 在哪 |
|---|---|---|
| 颜色、字号、字重、圆角、间距、阴影、断点 | 令牌，只在这一个文件里定义 | `web/src/tokens.css` |
| 按钮、输入框、多行输入框、下拉、表单项、状态标签、面板、提示、表格、对话框 | 基础组件，从 `index.ts` 引入 | `web/src/ui/` |
| 布局（排列、间距、宽度） | Tailwind 的工具类：`flex gap-2`、`p-4`、`w-full`（只在被扫描的目录里生效，见下面「Tailwind 只扫描哪些目录」） | — |

- **新代码不手写按钮、表单、标签、提示的样式。** 组件里没有的，先在 `web/src/ui/` 加组件，再在页面里用。
- **只用令牌里的颜色名**：`bg-surface`、`text-ink`、`text-ink-2`、`border-line`、`bg-fill`、`text-accent`，状态用 `bg-destructive/10` 这类。不写色值，不用 Tailwind 自带的调色板（`bg-blue-500` 不会生成）。
- **不写任意值**：`text-[13px]`、`p-[7px]`、`bg-[#fff]` 都不行。缺的值加到 `tokens.css`；颜色要同时给亮色和暗色（字号、圆角、间距只有一套）。
- **不写 `dark:`**：令牌按系统设置自动切换亮暗色。
- **不用 `block`、`grow` 这类和现有页面类名同名的工具类**：工具类会作用到现有页面里同名的元素。用 `flex-1` 代替 `grow`。
### Tailwind 只扫描哪些目录

- Tailwind 只扫描 `web/src/index.css` 的 `@source` 列出的目录：现在是 `web/src/ui/`（组件）、`web/src/shell/`（导航、外壳、设置页）和 `web/src/workbench/`（工作台）。**现有页面（`web/src/*.tsx`）没被扫描**：在页面里写 Tailwind 类，只有恰好也在被扫描的目录里用到的才生成样式，其余不生成、也不报错。
- 原因：现有页面的类名（`block`、`grow` 等）和工具类同名，扫描它们会生成同名的工具类，改掉现有页面的样式。
- 现有页面的布局继续用 `styles.css`。按新的信息结构重做页面时，新页面放进一个新目录，把它加到 `index.css` 的 `@source`。`tests/web-ui.test.ts` 从 `@source` 读检查范围，加进去就会被查。

### `npm test` 查什么

| 测试 | 查什么 | 查不出什么 |
|---|---|---|
| `tests/web-tokens.test.ts` | `web/src` 里 `tokens.css` 以外直接写的颜色、字号、字重、字体、圆角，CSS 变量声明，任意值，默认调色板 | `styles.css` 里直接写的间距；写在声明下一行的颜色名等少数写法 |
| `tests/web-ui.test.ts` | `@source` 列出的目录（`ui/`、`shell/`）里带值的类是否生成了样式（缺令牌会被查出），以及有没有和现有页面类名同名的工具类 | 根部分拼错的类名（`itmes-center`）；没被扫描的目录；函数返回的页面类名 |

手写按钮、表单，用了 `dark:`，这类问题测试查不出来，靠评审。

### 组件怎么选

| 场景 | 用法 |
|---|---|
| 一个页面的主操作 | `Button`（默认变体），一组按钮里只有一个 |
| 次要操作、取消 | `Button variant="outline"` 或 `"ghost"` |
| 删除、覆盖、放宽权限 | `Button variant="destructive"`，点了先开 `Dialog` 确认 |
| 跳到别处 | 链接（`<a>`），不是按钮。`Button variant="link"` 是长得像链接的按钮，只用于不跳转的动作（例如「展开日志」） |
| 任务、节点的状态 | `Badge`：`running` 进行中、`success` 完成、`warning` 等验收这类等待中的状态、`destructive` 失败、`pending` 未开始。提醒当前用户「这件事等你处理」用 `accent`（只用于这个意思）；普通小标签（例如「推荐」）用默认的 `neutral` |
| 操作结果、需要注意的限制、失败原因 | `Alert`：`success`、`warning`、`destructive` |
| 表单 | `FieldGroup` 里放 `Field`，每个 `Field` 里是 `FieldLabel`、控件、需要时加 `FieldDescription` 或 `FieldError` |
| 选项 2～5 个、要一眼看到全部 | 一组 `Button`；更多选项用 `Select` |
| 一块独立的内容 | `Card`，标题用 `CardTitle`，操作放 `CardFooter` |
| 列表数据 | `Table`（窄屏下在自己的框里横向滚动） |

### 状态和细节

- **提交中**：按钮 `disabled`，文字改成进行中的说法（「正在保存…」）。
- **校验失败**：`Field` 加 `data-invalid`，控件加 `aria-invalid`，`FieldError` 写原因。
- **数字列**：右对齐，加 `tabular-nums`。
- **长内容**：文本容器要能处理很长的输入（`wrap-anywhere`、`truncate`），flex 子元素加 `min-w-0` 才能截断。
- **空状态**：不显示空表格，写一句现在是什么情况和下一步做什么。
- **焦点**：可点的元素要有看得见的焦点样式。`Button` 和输入框、下拉已经带了；页面里自己写的链接和可点元素要自己加。

## 第二步：写界面上的文字

界面上的文字只为一件事：让人更容易看懂和操作。写之前先问：这句话不写，用户会不会做错或看不懂。不会就不写。

### 说明文字默认不写

- 不重复标题、标签、数值、状态和按钮上已经说了的内容。
- 只在这四种情况下写：选择不明显、有限制、有后果、有下一步。
- 一句只说一件事。能放进标签或占位提示的，不另写一段。

| 不好 | 好 | 为什么 |
|---|---|---|
| 「最多 34 个字符，在 github.com 上全局唯一，到那边还能再改。」 | 「最多 34 个字符，不能和 GitHub 上已有的 App 重名。」 | 留下限制，删掉安慰的话（「到那边还能再改」） |
| 「点击下方按钮保存你的修改。」 | 不写 | 重复了按钮的动作 |
| 「状态：已完成」旁边再写「任务已经完成了」 | 只留状态标签 | 重复了状态 |

### 用用户的说法

- 按用户要做的事起名，不按系统怎么实现起名：写「通知」，不写「webhook 配置」。
- 同一个东西在所有页面用同一个名字。

### 按钮和动作

- 按钮写动作，用动词开头：「保存」「删除凭据」「到 GitHub 注册」，不写「确定」「提交」「下一步」这类看不出后果的词。
- 同一个动作从头到尾用同一个词：按钮「保存」，完成后提示「已保存」。
- 进行中用「正在……」，结尾用省略号「…」：「正在保存…」。

### 出错和空状态

- 错误说清楚发生了什么、怎么改：「令牌没有这个仓库的写权限，在凭据页换一个有写权限的令牌。」
- 错误不道歉，不含糊：不写「出了点问题」「抱歉」。
- 空状态给下一步：「还没有任务。新建一个任务，从一句需求开始。」

### 格式

- 界面文字用中文，用中文标点。
- 中文和英文、数字之间加一个空格：「App 名字」「最多 34 个字符」。
- 数量用阿拉伯数字。
- 不用感叹号，不用营销式的形容词。
- 产品名、命令、标识符原样写（`EOS_PUBLIC_URL`、`github.com`），代码类的内容用等宽字体。

## 第三步：检查无障碍

- 只有图标的按钮要有 `aria-label`（例如对话框的「关闭」）；装饰性图标加 `aria-hidden="true"`。
- 表单控件都有标签：`FieldLabel` 的 `htmlFor` 对上控件的 `id`。
- 动作用 `<button>`，跳转用 `<a>`；不在 `div`、`span` 上绑点击。
- 标题按层级（`h1` → `h2` → `h3`），不跳级。
- 对话框一定有 `DialogTitle`；不想显示标题时给它 `className="sr-only"`。
- 不禁止缩放，不拦截粘贴。
- 颜色不是唯一的信息：状态标签有文字，错误有文字说明。

## 第四步：截图并附在 PR 里

改了界面外观的 PR 都要附截图。截图放在 `docs/e2e/<这次的目录>/` 下，PR 描述的「能用证据证明的」里写路径。截图不代替 E2E：改 `web/` 仍要按 `CLAUDE.md` 自检第 3 条做端到端验证。

| 改了什么 | 怎么截 | 要有哪些 |
|---|---|---|
| 页面 | Playwright 打开页面截图，参考 `scripts/web-pixels.ts` 的做法；它的页面清单只有 10 个页面，改到清单外的视图（例如卡点、对比）要自己加 | 改到的每个页面：1440 宽和 390 宽，亮色和暗色 |
| 组件 | `node --import tsx scripts/web-ui-gallery.ts <输出目录>`，样张在 `scripts/ui-gallery/` | 新组件或改了的组件加进样张；`gallery-report.json` 和截图（亮暗色 × 1440/390 宽，另有亮色下对话框打开时的两张） |
| 只改底层、页面不应该变 | 先跑 `scripts/e2e-ci.ts` 得到数据目录 `.eos/e2e/data`；用它接连截改动前、改动后的构建（每次先 `npm run build:web`），再 `scripts/web-pixels.ts compare` | 比较结果（存进 `docs/e2e/`），清单里的全部截图逐像素相同 |

- **390 宽必须截**，并确认不横向滚动（`document.documentElement.scrollWidth <= window.innerWidth`）。`web-ui-gallery.ts` 会查；`web-pixels.ts` 不查，要自己看。
- 截图前等页面稳定：固定时钟，等数据加载完，连续两次截图相同再保存（`scripts/web-pixels.ts` 是这样做的）。
- 自己先看一遍截图再交：文字截断、重叠、对比度不够、暗色下看不清，都在这一步发现。
- 浏览器 E2E 按页面结构定位元素（类名、按钮文字）。改了这些，同一个 PR 里改对应的脚本并跑一遍。`web-e2e.ts`、`improve-web-e2e.ts`、不带 `--fake` 的 `chat-web-e2e.ts` 调用真实模型，算进每个 PR 最多 1 次的限制。

这些规则从下面几处挑选、改写成适合 Eos（团队工具、中文界面）的版本。原文没有装进仓库。

| 来源 | 借用了什么 |
|---|---|
| shadcn/ui 的 base-nova 样式（Base UI 版） | 组件的结构和变体 |
| Multica（提交 1054347）`AGENTS.md` 的「UI Copy」 | 说明文字默认不写、只在四种情况下写 |
| anthropics/skills 的 frontend-design 中写文案的部分 | 按用户的说法起名、按钮写动作、出错和空状态 |
| vercel-labs/web-interface-guidelines（提交 434b7f9） | 无障碍、表单、长内容、数字列的检查项 |
